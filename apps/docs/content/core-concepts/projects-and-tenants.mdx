# Projects and Tenants

Zyvan is engineered from the ground up for high-throughput, multi-tenant B2B platforms. In modern SaaS applications, your platform serves thousands of distinct customer organizations—each with different traffic patterns, varying destination server capacities, and independent reliability requirements.

Zyvan manages this through a two-tiered isolation hierarchy: **Projects** and **Tenants**.

```text
Organization (Your Company)
   ├── Project: Production (prj_prod_01...)
   │      ├── Tenant: Acme Corp (concurrency: 20, rate: 200/s)
   │      │      └── Destinations [Webhooks, Slack, DataDog]
   │      ├── Tenant: Globex Corp (concurrency: 5, rate: 50/s)
   │      │      └── Destinations [ERP Webhook]
   │      └── Tenant: Initech (concurrency: 10, rate: 100/s)
   └── Project: Staging (prj_stg_02...)
```

---

## 1. Projects (Primary Isolation Boundary)

A **Project** is the top-level operational boundary in Zyvan. Projects represent isolated environments and security realms:

- **API Keys & Authentication**: API keys (`zyv_live_...`, `zyv_test_...`) are strictly scoped to a single Project.
- **Environment Isolation**: Separate `production`, `staging`, and `development` environments into distinct projects to ensure test events never pollute production delivery pipelines.
- **Quota & Billing Boundaries**: Overall throughput allowances, data retention periods, and plan limits are tracked per project.

---

## 2. Tenants (Noisy-Neighbor Protection)

A **Tenant** represents an individual customer account, workspace, or organization within your platform.

### The Noisy-Neighbor Vulnerability

In naive webhook delivery systems, all outgoing webhooks are pooled into a single flat FIFO queue:

```text
[Acme 1] [Acme 2] [Acme 3] ... [Acme 50,000 Burst] ──► [Globex 1 (Blocked for 45 minutes!)]
```

If one high-volume customer (Acme Corp) triggers a massive batch operation, or if Acme's webhook server experiences an outage and takes 10 seconds to time out on every request, **workers become saturated, starving all other customers (Globex, Initech) of delivery capacity**.

Zyvan eliminates this with **per-tenant fair-share scheduling**:

```mermaid
graph TD
    Queue[Unified Event Ingestion] --> Router[Tenant Concurrency Router]
    
    Router --> T1[Tenant: Acme Corp<br/>In Flight: 10/10 (Maxed)<br/>Excess held in buffer]
    Router --> T2[Tenant: Globex Corp<br/>In Flight: 1/5<br/>Dispatched Immediately]
    Router --> T3[Tenant: Initech<br/>In Flight: 2/10<br/>Dispatched Immediately]

    T2 --> WorkerPool[Active Worker Delivery Pool]
    T3 --> WorkerPool
```

## Tenant Controls & Rate Limiting

You can configure granular limits for each tenant:

| Parameter | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `concurrency_limit` | `integer` | `10` | Maximum simultaneous in-flight HTTP connections across all destinations for this tenant. |
| `rate_limit` | `integer` | `100` | Token-bucket rate limit (requests per second dispatched). |
| `status` | `string` | `ACTIVE` | Operational status: `ACTIVE` or `PAUSED`. |

### Dynamic Concurrency Semaphores

When a worker prepares to dispatch a delivery:
1. It acquires a lease on the tenant's concurrency semaphore in Redis/PostgreSQL.
2. If the tenant currently has reached their `concurrency_limit` (e.g. 10 in-flight requests), the delivery is queued in the tenant's fair buffer.
3. As soon as an active request completes, the semaphore releases and the next delivery dispatches.
4. **Other tenants with available concurrency are never blocked or delayed.**

## Managing Tenants via SDK

### 1. Tagging Events with a Tenant ID

When publishing events from your application, include the `tenantId`:

```typescript
import { ZyvanClient } from '@zyvan/sdk';

const zyvan = new ZyvanClient({
  apiKey: process.env.ZYVAN_API_KEY!,
  projectId: 'prj_live_01H8X92M4Q',
});

// Publish event scoped to a specific customer tenant
await zyvan.events.create({
  eventType: 'subscription.renewed',
  tenantId: 'cust_acme_corp',
  idempotencyKey: 'sub_renew_acme_2026_03',
  payload: { plan: 'enterprise', seats: 250 },
});
```

### 2. Updating Tenant Quotas & Pausing Deliveries

If an individual customer is undergoing server maintenance or experiencing a denial-of-service attack on their receiver endpoint, you can pause deliveries exclusively for that customer:

```typescript
// Pause deliveries for a specific tenant during customer downtime
await zyvan.tenants.update('cust_acme_corp', {
  status: 'PAUSED',
});

// Later, resume deliveries and update quotas
await zyvan.tenants.update('cust_acme_corp', {
  status: 'ACTIVE',
  concurrencyLimit: 25, // Upgrade concurrency for high-tier account
  rateLimit: 500,       // Upgrade rate limit to 500 req/s
});
```

<Callout type="tip" title="Customer-Facing Webhook Portals">
  Because Zyvan isolates delivery history by `tenantId`, you can build customer-facing webhook logs and debug dashboards directly inside your application by passing `tenantId` to Zyvan API queries.
</Callout>
